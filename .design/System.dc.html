HUD rules
Three docks, and nothing floats outside them. Every value below is already in css/styles.css — this reorganises, it does not repaint.

1 · Three docks, never more

play
Top — status. One row that never wraps. Read-only, plus one menu.
Right — tools. Things you open: quests, shop, mentor, recentre. Starts below the status bar so the two never collide.
Bottom — actions. Things you do, plus the one next step.
Everything between the docks is the game. Nothing new may be placed there — a toast, a coach, a banner all dock to the bottom.

2 · What a colour means

Green — run it. One per screen, the only round button. Never used for anything else.
Violet — write code. The path into the editor.
Amber — build and progress. Build mode, XP, the next step. Already the game's accent (#ffb830) — now it means one thing.
Glass — everything else. Tools and secondary controls recede.
Red — attention only. Badges and stop. Never a resting button.

3 · The same shape means the same thing

Circle, 64px — run. Exactly one on screen.
Pill, 54px tall — a primary action with a word on it.
Rounded square, 44px — a tool. Icon only, always 44 so it stays tappable.
Small pill — a number you read, never tap.

4 · Icons, not emoji

The chrome already swaps emoji for drawn SVG (js/ui-icons.js). Keep that for every control: emoji render differently on each device and are the fastest way for a store screenshot to look unfinished. Emoji stay where they are content — the world, block labels, lesson text.

5 · What a new player sees first

Top left: what I have. Top right: one menu. Bottom: one sentence telling me what to do next, and three buttons — write code, build, run. That is the whole game, learnable in one glance, and it reads the same in a store screenshot as it does in the hand.
